# 本机记忆

这台机器的 AI 共用 OptMem 日志与二叉树。记忆帮助找回过去的依据；当前文件说明现在的状态，用户本次明确要求优先。

## 何时使用

缺少的历史信息可能改变本次判断或操作时，先检索：

- 用户问以前做过什么、为什么选择某个方案，或某种方法是否已经试过。
- 接续项目，但当前对话缺少进度、待办、失败原因或恢复入口。
- 准备沿用或改变旧决定，需要确认原来的理由、约束及是否已经被替代。
- 任务依赖用户的长期偏好或条件，而当前上下文没有这些信息。

当前对话已给出足够依据，或只是一般解释、计算、改写所提供的材料，就直接完成任务。不要为每轮回复重复检索，也不必为保存每条笔记先做语义搜索。

认真完成的工作、持续有效的决定、经验、用户偏好和有长期影响的事件需要记一条最终状态；临时调试、重复陈述和没有结果的打算不用记。

## 检索与证据

执行命令前读 [本机入口](references/local-paths.md) 和 [命令说明](references/commands.md)，将别名展开为完整命令。

- 记得编号、文件名或专名时，用关键词检索；只记得大概意思时，用语义检索。先限定已知项目，必要时再扩大范围。
- 已索引项目的问题，优先用项目检索，将历史与当前文件一起核对。需要论文或研究节点时再读 [关联树](references/trees.md)。
- 普通检索或启动摘要中的旧决定，先检查关系再沿用。需要旧方案本身时保留历史模式。
- 只读取能解决当前问题的条目。涉及精确原话、冲突或会影响操作的依据时，展开来源并核对原对话或文件。
- 搜索结果不完整或模型不可用时说明具体缺口；可继续关键词检索，不把关键词结果说成语义搜索。缺少的历史会影响安全执行时，不猜测补齐。

## 记录与决定变化

- 笔记以实际项目名 `[project]` 开头；没有项目时用 `[general]`。一行最多 280 UTF-8 字节，写最终结果、理由和成果位置。
- 使用 `note` 写入。若它要求压缩，在下一步前完成打印出的压缩，直到没有待办；不直接改写记忆数据文件。
- 自动去重保留全部来源。语义去重只归并同一事实或事件，不能吞掉新的日期、结果、范围或失败记录。
- 用户已明确采用新决定时，写清实际变化，再建立 `replaces` 关系。新增细节用 `enriches`，未解决的分歧用 `challenges`；提议、计划和待测方案不能写成已采用的决定。
- 关系只连接已有条目，不猜编号或来源；不确定时保留各条记录。后台会分批审阅新记录，不保证即时建立关系。

子代理不运行 `memo`，也不写共享记忆。将结果交给主代理判断是否需要记录。
